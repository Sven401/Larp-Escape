# Bounded file staging, version1

This slice completes the narrow temporary-source file port under the existing ESP filesystem owner. It does not establish verified peer identity, SDK event origin or radio delivery. Raw callback/input queue, one-item application owner, original rights/revisions/deadlines, private import receipt, Apply and copied responses remain the existing [profile control path](profile-controls-v1.md).

## Shared bounded source

ProfileFileStaging implements IProfileStagingStore over a trusted synchronous IProfileTemporaryFilePort. Begin accepts1..131072 bytes, append freezes1..120 copied bytes before the port call, seal requires the exact declared length, read permits only that exact complete source and a real end after its last byte. A short source, extra byte, read error or invalid read status fails without changing the caller byte. Repeated End performs no further file read. IO failure fences every operation except discard; failed discard keeps the fence until a successful retry. Invalid arguments perform no IO. Reentrant begin/append/seal/read/discard perform no nested IO; this is a sole-owner fence, not a thread mutex.

The host tool's existing TemporaryProfileFile now uses this same bounded implementation with actual std::tmpfile. No third Profile or document buffer was added. Existing framing/receiving/importing CLI uses the shared core. The low file port is a trusted internal interface; callers do not use it to bypass the bound.

## ESP mounted owner

Esp32ProfileStagingStore is a child of process-lifetime Esp32ProfileStore. Only the stopped application owner calls it. This is a trusted caller precondition, not an implicit game-state check inside the filesystem adapter. Future connected dispatch must enforce the stopped IO context for collection and cleanup, including overlapping game-start requests; current firmware probe performs its roundtrip before Application startup. It never mounts, unmounts, grows, formats, renames a profile or selects a client path. The mount owner still registers fixed `/larp-profiles`, label `spiffs`, format/grow=false. One original child owns the claim through open, write, seal, read and cleanup; another child cannot touch or remove it. Cleanup failure retains that claim until confirmed retry. Children must outlive their use and be destroyed before the mount owner; failed destructor cleanup keeps a mount-owned cleanup fence even after child destruction/address reuse. A new child must successfully discard the old temporary source before beginning; merely reusing the old address cannot reopen it.

Only `/larp-profiles/profile-source.tmp` is opened/removed. `/larp-profiles/profile-a.larp` and `profile-b.larp` remain the existing journal records. Begin truncates only a previous-boot temporary source; no restore/import/resume of those stale bytes. Discard closes the temporary stream, removes only this fixed name and accepts ENOENT as already absent. Flush/close failure during seal leaves no readable source; successful seal closes the writer and opens an actual `rb` descriptor at the beginning. Read-only safety also requires the documented exclusive filesystem owner: no external writer/unmount changes the named source. Temporary completion uses flush/close/reopen, with no fsync or durable-save claim; later JournalCommit uses the existing distinct flush/fsync/close contract.

The pinned installed LittleFS1.10.0 SDK header was inspected. [Upstream VFS implementation](https://raw.githubusercontent.com/joltwallet/esp_littlefs/v1.10.0/src/esp_littlefs.c) maps named file IO to LittleFS, including failure results. This is an API/source check, not equivalence proof of its prebuilt archive or physical flash acceptance. File IO has stdio/FS heap and latency costs; byte/copy limits do not prove a wall-clock deadline. The input callback never performs these operations.

## Vertical proof and narrow firmware probe

Native executes the actual Esp32ProfileStore/Esp32ProfileStagingStore source bodies against a deterministic mount/named-VFS shim. Backing streams are real host tmpfiles, with explicit open/partial-write/flush/close/reopen/read/remove faults. Only the three exact whitelist names are available, no host device path is accessed. This is an isolated source-local stdio substitution, not a production path or runtime option. The real pinned ESP headers/library are compiled separately in the firmware build.

Actual Raw gate→copied input queue→ESP file adapter/model→source→private import/control→Apply/synthetic owners/host journal→copied output queue→reader/sender yields172 ATT copies and three semantic responses, ending Saved cfg2/profile4/generation2. The temporary source is deleted before Apply; no VFS journal path is touched by staging. Journal confirmation in this test comes from the existing host journal model, not the VFS shim or physical flash. Independent counterpart correlates actual Saved bytes and scoped observations.

The isolated ProfileRuntimeProbe has a one-byte disposable-file roundtrip after its existing explicitly nonformatting mount and before Application startup. It reports imported=false/saved=false/network=false and stops on any file error. This source change was compiled only; no new upload or device execution. The production entry still uses the legacy Controller and has no new transport hook.

Still open: real credential verifier/explicit durable GM/provisioning, original SDK lifecycle/service/bearer, production layout/reserve/owners, physical filesystem/flash failure/reboot/free-space exhaustion, RF/Android/SMP/time/stack/heap/energy. No upload/format/remote operation.
