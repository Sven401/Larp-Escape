# Profile controls and responses, version 1

This narrow vertical path connects the actual copied FreeRTOS queue, temporary source, private Application receipt and controlled Apply to a bounded response. The Tool emits controls; Native tests execute the actual source/Application/owners/journal model. Real SDK profile attributes/security/bearer/temporary storage and Android remain open.

## Bytes

All integers little endian, no padding or client authority field. Command: exactly12 bytes, `version:u8=1, kind:u8=7, transfer:u16>0, operation:u8, reserved:3zero, request:u32>0`. Operations Finish1 / Abort2 / Apply3. The existing kind5 metadata and kind6 data remain unchanged. The queue accepts exact validated kind7 values; game-command assembly still rejects profile kinds.

Response: exactly20 bytes, `version:u8=1, kind:u8=8, transfer:u16>0, request:u32>0, operation:u8, code:u8, detail:u16, draftRevision:u32, configurationRevision:u32`. Response correlation is the originating transfer/request/operation on its original verified connection. Code1 DraftReady,2 ApplyQueued,3 Saved,4 Aborted,5 ReceiveRejected,6 ImportRejected,7 ApplyRejected,8 Unauthorized,9 RequestConflict,10 RequestExpired,11 OutOfOrder,12 Expired,13 ApplyFailed. Success1..4 requires detail0;1..3 positive revisions. DraftReady belongs to Finish, Queued/Saved/ApplyFailed to Apply, Aborted to Abort. Unsupported codes/details/lengths preserve decode destination; encoder failure writes0 and preserves output.

Detail0 None,1 Busy,2 WrongTransfer,3 Incomplete,4 DigestMismatch,5 StorageFailure,6 InvalidSource,7 NotReady,8 GameRunning,9 StaleRevision,10 NoReceipt,11 Failed. This explicit vocabulary is independent of internal C++ enum ordinals. Unauthorized input/closed original connection normally emits no response; code8 is reserved for a future authenticated rejection policy, never a route relabel.

## Owner and request history

ProfileTransferControl is the sole synchronous Application owner, never a transport callback or cross-task API. ProfileFramePump polls source and controller even while input is blocked, takes at most one copied item and dispatches kind7 only when a control sink is present and ready. The legacy metadata/data-only pump has no implicit finish. One response slot and one private receipt/cache are fixed storage. Pending response or selected Apply prevents further queue takes; backpressure/QueueFull is explicit, no dropped success or unbounded response list. Caller uses offerResponse into the [actual copied FreeRTOS output port](profile-response-queue-v1.md); only Copied releases output. Owner and transport sender retain separate task ownership.

Requests start at1 for each verified original principal/epoch and advance exactly once without wrap. A consumed operation error also advances the sequence. Exact same last request/transfer/operation returns its cached snapshot without reimport/activation; same ID with changed operation/transfer yields Conflict; older ID Expired; gaps OutOfOrder. These history errors and queue-age expiry do not consume a new request. Cache holds only the most recent consumed request, not a whole transfer log. After real authority closure/new epoch, private proof/history/old replies close. This is volatile local deduplication, not cryptographic authentication, durable replay protection or a boot token. The real verifier/connection-generation lifecycle is still required. A historical repeated response describes that operation, not a current status snapshot.

New successfully started metadata clears the prior private receipt while retaining monotonic request history. Transfer IDs are correlation only; reusing one never recreates a receipt. Client must retain its request sequence or reconnect through the verified lifecycle; this20-byte reply does not provide a counter recovery/query API.

## Operations

Finish explicitly seals exact source length/CRC, imports through actual private Application storage with original rights/revisions/stopped-game checks, and closes the temporary source. Successful import **and** successful cleanup issue DraftReady and retain only the private server receipt. Incomplete/corrupt/IO/semantic/running/stale/late-rights failures cannot supply an Apply proof. Cleanup failure invalidates the proof even if a local parsed draft remains. Finish duplicates replay the cached result without reading an ended source again.

Apply selects only the internally issued receipt matching original connection/transfer/Application, rechecks rights, stopped game, readiness and both revisions through applyImportedProfile, and returns ApplyQueued. No client response can be deserialized into proof. Receipt has no new TTL; a freshly received Apply may select an accepted draft after the collection deadline, provided original authority/revisions still match. A new source/Abort/local draft change closes or invalidates it.

Application and hardware owners run their normal service separately. Control service adds no game tick. Once Application is no longer busy, it emits Saved only if actual phase Ready, operation Apply, confirmed storedMatchesActive/hasStoredProfile and exact target configuration/profile/stored generations all match. Otherwise ApplyFailed, including uncertain journal completion. An already running game does not erase a previously confirmed save; this path never starts a game. Queued and Saved share the Apply request and are distinct stages. Duplicate Apply after completion returns final cached Saved/Failed without another journal write. Selected hardware work completes under existing Application policy if rights disappear later; no reply is relabeled onto a new connection.

Abort before Apply closes only the temporary source and private receipt. It retains any local parsed draft and confirmed active/journal/game. Abort queued after a selected Apply waits behind that transaction/final response; it cannot cancel or roll back selected hardware work. A wrong transfer cannot discard another source/proof. Backend discard failure is visible as ReceiveRejected/StorageFailure.

## Time and response priority

Source collection/Finish/import keep the original120000ms metadata timestamp, including queue waiting, without refresh. Every copied queue item retains the existing outer120000ms age/future check; a rejected outer item may have no control response. In addition, control admission allows less than10000ms since its trusted callback time. This separate local policy is not the2000ms game command framing deadline and has no measured radio guarantee. A new retry callback timestamp does not extend source collection. uint32 elapsed arithmetic requires observation within a counter cycle.

Response lifetime is less than10000ms from owner production, carried as trusted producedAt metadata through take/load. Loading, Busy and retry never refresh that timestamp. The transport sender owns an immutable20-byte value, rechecks exact principal/epoch before each attempt and requires the bearer to recheck original generation again before copy. Busy retries identical bytes; Unavailable/expiry/revocation discard pending output. Copied means local bearer copy, never peer indication confirmation or application acknowledgement.

serviceProfileConfiguredFrames captures priority before service: game replies first, then profile response, then status. Even the step completing a higher priority reply defers lower senders; at most one bearer call/step and no added Application tick. Caller supplies a bearer supporting at least20-byte values. The copied cross-task port is implemented separately; real bearer attribution/physical timings remain separate acceptance.
